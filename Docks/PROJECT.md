# PROJECT.md — LinkMesh (ابزار لینک‌سازی داخلی هوشمند)

---

## هدف بیزینس

ابزاری برای تیم‌های SEO که به‌صورت خودکار لینک‌های داخلی بهینه را بر اساس شباهت معنایی و دسته‌بندی صفحات پیشنهاد می‌دهد. فاز اول برای سایت نهال‌گشت (فروش تور مسافرتی) ساخته می‌شود؛ معماری به‌گونه‌ای طراحی شده که در فازهای بعدی به ابزاری عمومی برای هر سایتی قابل تبدیل باشد.

---

## پرسونای هدف

کارشناس SEO یا مدیر محتوا که با CSV کار می‌کند، کدنویسی بلد نیست، و نیاز دارد خروجی خود را به‌سرعت export کند.

## نبایدهای سخت‌گیرانه (Anti-Patterns)

این لیست مطلق است. مدل کدنویس تحت هیچ شرایطی از این موارد استفاده نمی‌کند:

| ممنوع | دلیل / جایگزین |
|---|---|
| Firebase، Supabase، هر backend خارجی | پروژه کاملاً client-side است؛ از Dexie.js استفاده کن |
| `sql.js` یا `@sqlite.org/sqlite-wasm` | Dexie.js کافی است و پیچیدگی WASM لازم نیست |
| Redux، Zustand، MobX | از React useState/useContext استفاده کن |
| Styled-components، CSS Modules، inline style | فقط Tailwind CSS کلاس مجاز است |
| هر مدل Gemini غیر از `gemini-3-flash-preview` | برای کنترل هزینه — مدل ثابت است |
| ذخیره API Key در Dexie یا کد | فقط `localStorage` برای API Key |
| ارسال همه صفحات یکجا به Gemini | پردازش صفحه‌به‌صفحه با صف و ذخیره دانه‌دانه الزامی است |
| محدودیت تعداد لینک (max_links) | AI تمام لینک‌های مرتبط را انتخاب می‌کند — بدون محدودیت عددی |
| `axios` | از fetch native مرورگر استفاده کن |
| `moment.js` یا `date-fns` | از `new Date().toISOString()` استفاده کن |
| کامنت‌گذاری به انگلیسی در کد | تمام کامنت‌ها فارسی باشند |
| **میانگین‌گیری از فاکتورهای شباهت** | فاکتورها باید «تکمیل‌کننده» هم باشند نه میانگین — از سیستم امتیازدهی چندلایه استفاده کن |
| **نادیده گرفتن منطق فصلی/زمانی** | اگر صفحه مقصد ماه خاصی دارد، ماه بعدی مجاز است ولی ماه قبلی و فصل‌های دیگر نه |

## قوانین کلیدی الگوریتم (Business Rules)

### ۱. قانون «Reactivity تنظیمات»
وقتی کاربر در صفحه Config تغییری در `scoring_mode` یا `weights` می‌دهد، سیستم **باید** بلافاصله کاندیداهای جدول `candidates` را پاک کند و مجدداً محاسبه کند. این محاسبه باید **قبل از** ادامه پردازش AI انجام شود.

### ۲. قانون «فیلتر فصلی/زمانی»
- اگر صفحه منبع `ماه_تقویمی_برگزاری` دارد (مثلاً آبان)، کاندیداها باید:
  - **مجاز:** همان ماه یا ماه بعدی (آبان، آذر)
  - **غیرمجاز:** ماه‌های قبلی یا فصل‌های دیگر
- اگر صفحه منبع `فصل_برگزاری` دارد (مثلاً تابستان)، کاندیداها باید فقط از همان فصل باشند
- **استثنا:** صفحات عمومی (بدون ماه/فصل خاص) می‌توانند به هر صفحه‌ای لینک شوند

### ۳. قانون «اولویت مبدا/مقصد»
ترتیب اولویت در امتیازدهی:
1. **مبدا یکسان** (اولویت اول) — `شهر_یا_استان_مبدا`
2. **مقصد یکسان** (اولویت دوم) — `شهر_یا_جزیره_مقصد`
3. **کشور یکسان** (اولویت سوم) — `کشور_مقصد`

### ۴. قانون «امتیازدهی چندلایه (نه میانگین)»
فاکتورها به صورت لایه‌ای اعمال می‌شوند:
1. **لایه اول — فیلتر Hard:** فصل/زمان نامعتبر = حذف کامل از لیست
2. **لایه دوم — امتیاز اصلی:** مجموع وزن تگ‌های مشترک (بدون میانگین)
3. **لایه سوم — بونوس مبدا/مقصد:** امتیاز اضافی برای تطابق مبدا یا مقصد
4. **لایه چهارم — مرتب‌سازی نهایی:** بر اساس امتیاز کل

## محدودیت‌های فازبندی

### فاز ۱ (این پروژه — در حال ساخت)
- ورودی فقط از طریق آپلود دستی CSV
- تحلیل AI روی متادیتای ۱۸ ستون دسته‌بندی
- امتیازدهی درون‌برنامه‌ای بدون AI (پیدا کردن top 20 کاندیدا)
- تحلیل AI دانه‌به‌دانه با صف و ذخیره‌سازی فوری
- صفحه جزئیات هر صفحه با قابلیت ویرایش دستی
- خروجی: export CSV / کپی به کلیپ‌بورد

### فاز ۲ (آینده — اکنون لمس نشود)
- کراولر خودکار برای استخراج تگ‌ها از سایت
- چند کاربر / چند workspace
- ذخیره‌سازی ابری
